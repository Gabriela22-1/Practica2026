Moștenirea în Lanț în C#

Programare Orientată pe Obiecte

Introducere în moștenire și analiza detaliată a moștenirii în lanț cu exemple practice.

Introducere

Ce este moștenirea în POO?

Moștenirea este unul dintre cele patru piloni fundamentali ai programării orientate pe obiecte, alături de încapsulare, polimorfism și abstractizare. Ea permite unei clase noi să preia (să moștenească) proprietățile și metodele unei clase deja existente, fără a rescrie codul de la zero.

Clasa din care se moștenește se numește clasă de bază (sau părinte), iar clasa care moștenește se numește clasă derivată (sau copil). În C#, moștenirea se declară folosind simbolul :.

Moștenirea nu este un mecanism de copiere a codului — este un mecanism de modelare a realității. Dacă modelarea este greșită, aplicația devine instabilă. Dacă este corectă, aplicația devine scalabilă.

Sintaxa în C#
class Animal
{
    public string Nume { get; set; }
}

// Caine mosteneste din Animal
class Caine : Animal
{
    public string Rasa { get; set; }
}
Context

Tipuri de moștenire în C#

01

Moștenire simplă

O clasă derivată moștenește dintr-o singură clasă de bază.

A → B
02

Moștenire multiplă

În C# nu este permisă între clase. Se realizează exclusiv prin interfețe, evitând ambiguitățile.

A + B → C (interfețe)
03

Moștenire în lanț

O clasă derivată devine la rândul ei clasă de bază pentru o altă clasă.

A → B → C
04

Moștenire ierarhică

O singură clasă de bază este moștenită de mai multe clase derivate.

A → B, A → C
Conceptul principal

Moștenirea în Lanț — Multilevel Inheritance

Definiție

Ce este?

Moștenirea în lanț este mecanismul prin care o clasă derivată devine la rândul ei clasă de bază pentru o altă clasă, formând astfel un lanț ierarhic de specializări progresive.

Structura de bază: A → B → C, unde B moștenește din A, iar C moștenește din B. Clasa C are acces la membrii din toate clasele din lanț.

Cuvinte cheie esențiale

Mecanisme C#

  • base() — apelează constructorul clasei de bază directe
  • virtual — marchează o metodă ca suprascriptibilă
  • override — suprascrie metoda virtuală din bază
  • protected — accesibil în clasă și în toate derivatele
Avantaje

De ce să folosim?

  • Cod reutilizabil la fiecare nivel al ierarhiei
  • Specializare progresivă — fiecare nivel adaugă comportament
  • Reflectă natural relații din lumea reală
  • Polimorfism prin metode virtuale la toate nivelurile
Dezavantaje și atenție

Când poate fi problemă?

  • Cuplaj strâns — modificările din bază se propagă în tot lanțul
  • Ierarhii prea adânci (5+) devin greu de înțeles și întreținut
  • Fragilitatea clasei de bază — o schimbare mică poate strica derivatele
  • Dificil de testat izolat fiecare nivel

Modul de utilizare

Când și unde se aplică?

Situații reale

Exemple din practică

  • Utilizator → Angajat → Manager
  • Produs → ProdusElectronic → Laptop
  • Cont → ContCurent → ContPremium
  • Vehicul → Mașină → Mașină electrică
Reguli de utilizare

Când este potrivită?

  • Există o relație clară de tip „este un" între clase
  • Fiecare nivel adaugă date sau comportament nou
  • Ierarhia nu depășește 3–4 niveluri de adâncime
  • Se aplică în aplicații mari unde organizarea clară este critică
Exemple practice

Cod în C# — Ierarhia Utilizator → Angajat → Manager

Exemplu complet cu 3 niveluri de moștenire în lanț — din tema profesorului Inculeț Iulian.

Nivelul 1 — Clasa de bază: Utilizator

class Utilizator
{
    public int    Id     { get; set; }
    public string Nume   { get; set; }
    public string Email  { get; set; }
    public string Parola { get; set; }

    public Utilizator(int id, string nume, string email, string parola)
    {
        Id = id; Nume = nume; Email = email; Parola = parola;
    }

    public void Login(string parolaIntrodusa)
    {
        if (parolaIntrodusa == Parola)
            Console.WriteLine(Nume + " s-a autentificat cu succes.");
        else
            Console.WriteLine("Parola incorecta.");
    }

    public void Logout()
        => Console.WriteLine(Nume + " s-a delogat.");

    // virtual — poate fi suprascrisă în clasele derivate
    public virtual void AfisareInfo()
    {
        Console.WriteLine("Utilizator:");
        Console.WriteLine("ID: " + Id + ", Nume: " + Nume + ", Email: " + Email);
    }
}

Nivelul 2 — Angajat moștenește Utilizator

class Angajat : Utilizator   // moștenește Utilizator
{
    public double Salariu      { get; set; }
    public string Departament { get; set; }

    public Angajat(int id, string nume, string email, string parola,
                   double salariu, string departament)
        : base(id, nume, email, parola)   // apelează constructorul Utilizator
    {
        Salariu = salariu;
        Departament = departament;
    }

    public void Lucreaza()
        => Console.WriteLine(Nume + " lucrează în departamentul " + Departament);

    // virtual — Manager o va putea suprascrie
    public virtual double CalculeazaBonus() => Salariu * 0.10;

    public override void AfisareInfo()
    {
        Console.WriteLine("Angajat:");
        Console.WriteLine("Nume: " + Nume + ", Dept: " + Departament);
        Console.WriteLine("Salariu: " + Salariu + ", Bonus: " + CalculeazaBonus());
    }
}

Nivelul 3 — Manager moștenește Angajat (lanțul continuă)

class Manager : Angajat   // moștenește Angajat → lanțul: Utilizator → Angajat → Manager
{
    public int    NumarEchipa       { get; set; }
    public double BugetDepartament  { get; set; }

    public Manager(int id, string nume, string email, string parola,
                   double salariu, string departament,
                   int numarEchipa, double buget)
        : base(id, nume, email, parola, salariu, departament)
    {
        NumarEchipa = numarEchipa;
        BugetDepartament = buget;
    }

    public void AprobaConcediu(string numeAngajat)
        => Console.WriteLine("Managerul " + Nume + " a aprobat concediul pentru " + numeAngajat);

    // suprascrie CalculeazaBonus din Angajat — managerul primește 20%
    public override double CalculeazaBonus() => Salariu * 0.20;

    public override void AfisareInfo()
    {
        Console.WriteLine("Manager:");
        Console.WriteLine("Nume: " + Nume + ", Dept: " + Departament);
        Console.WriteLine("Echipă: " + NumarEchipa + ", Buget: " + BugetDepartament);
        Console.WriteLine("Bonus manager: " + CalculeazaBonus());
    }
}

Program principal — utilizare

static void Main(string[] args)
{
    Utilizator user = new Utilizator(1, "Ion Popescu", "ion@mail.com", "1234");
    Angajat    ang  = new Angajat(2, "Maria Ionescu", "maria@mail.com", "abcd", 8000, "IT");
    Manager    man  = new Manager(3, "Andrei Vasilescu", "andrei@mail.com", "admin",
                                   15000, "IT", 10, 500000);

    user.Login("1234");
    user.AfisareInfo();

    ang.Lucreaza();
    ang.AfisareInfo();

    man.AprobaConcediu("Maria Ionescu");
    man.AfisareInfo();
}

Ce demonstrează acest cod: Manager moștenește din Angajat, care la rândul lui moștenește din Utilizator — acesta este lanțul. Fiecare nivel apelează constructorul de deasupra lui prin base(). Metoda AfisareInfo() este virtual în Utilizator și suprascrisă (override) la fiecare nivel. Polimorfismul face ca o referință de tip Utilizator care conține un obiect Manager să apeleze versiunea din Manager.

Concluzii

Observații și reflecții personale

Ce am înțeles

Observații personale

Moștenirea în lanț devine cu adevărat puternică atunci când este combinată cu metodele virtuale și polimorfismul. Cuvântul cheie base() este esențial — fără el constructorii nu se inițializează corect pe toată ierarhia.

Cel mai dificil aspect a fost urmărirea ordinii de apel a constructorilor pe mai mult de 2 niveluri, și înțelegerea faptului că override la nivelul 3 suprascrie și versiunea de la nivelul 2.

Importanță practică

De ce contează?

Moștenirea în lanț se folosește în aplicații complexe, în sisteme mari, când construim extensii peste extensii.

Programatorii juniori o folosesc ca să scrie mai puțin cod. Programatorii seniori o folosesc ca să construiască arhitecturi coerente și ușor de extins.
